# Bounty Board — Technical Specification

**Описание:** веб-сервис для публикации заданий с виртуальным вознаграждением. Пользователи могут создавать задания, брать их в работу, отправлять результаты и получать баллы за успешно выполненную работу.

## 1. Технологический стек

| Компонент | Технология |
|---|---|
| Язык | Go |
| HTTP Framework | Gin |
| ORM | GORM |
| Database | PostgreSQL |
| Authentication | JWT |
| Контейнеризация | Docker + Docker Compose |
| API | REST |

## 2. Бизнес-требования

### 2.1. Пользователи
- Регистрация и авторизация.
- Просмотр профиля и баланса баллов.
- Просмотр рейтинга исполнителей.

### 2.2. Bounty Management
- Создание заданий с названием, описанием и наградой.
- Просмотр списка доступных заданий.
- Просмотр подробной информации о задании.
- Возможность закрыть или отменить собственное задание.

### 2.3. Task Execution
- Пользователь может взять доступное задание в работу.
- Одно задание может иметь только одного исполнителя.
- Исполнитель отправляет результат выполнения.
- Автор задания подтверждает или отклоняет результат.

### 2.4. Reward System
- После подтверждения выполнения исполнитель получает виртуальные баллы.
- Баллы начисляются только один раз.
- Баланс пользователя не может быть отрицательным.

### 2.5. Leaderboard
- Общий рейтинг пользователей по количеству заработанных баллов.
- Просмотр топ-10 исполнителей.

## 3. Основные сущности БД

| Entity | Основные поля |
|---|---|
| User | ID, Username, Email, PasswordHash, Balance |
| Bounty | ID, Title, Description, Reward, AuthorID, Status |
| Submission | ID, BountyID, ExecutorID, Result, Status |
| Transaction | ID, UserID, Amount, Type, BountyID |

## 4. Жизненный цикл задания

1. `OPEN` — задание опубликовано.
2. `IN_PROGRESS` — исполнитель взял задание.
3. `REVIEW` — результат отправлен на проверку.
4. `COMPLETED` — результат подтверждён, награда начислена.
5. `REJECTED` — результат отклонён и возвращён на доработку.

## 5. MVP — критерии готовности

- [ ] REST API для пользователей.
- [ ] JWT-аутентификация.
- [ ] CRUD для заданий.
- [ ] Механизм взятия задания.
- [ ] Отправка и проверка результатов.
- [ ] Начисление виртуальных баллов.
- [ ] Leaderboard endpoint.
- [ ] Docker Compose для запуска приложения и PostgreSQL.

## 6. Технические ограничения

- Подтверждение выполнения и начисление баллов должны происходить в одной DB-транзакции.
- Необходимо исключить повторное начисление награды.
- Одно задание не может быть одновременно взято несколькими исполнителями.
- Автор задания не может взять собственное задание.
- Все операции с заданиями должны проверять права пользователя.

## 7. Цель проекта

Получить небольшой, но полноценный backend-продукт с авторизацией, ролевой логикой, отношениями между сущностями, транзакциями и бизнес-ограничениями.
